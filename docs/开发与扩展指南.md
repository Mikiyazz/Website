# 开发与扩展指南

## 代码分层约定

同一模块中，`models.py` 定义持久数据和数据库约束，`selectors.py` 提供授权范围内的查询，`services.py` 执行业务状态变化，`views.py` 处理 HTTP 输入输出，`urls.py` 分配地址。没有相应需求的模块暂不创建空壳文件；后续有功能时再按约定增加。

一次写操作依次经过：登录会话 → 输入校验 → 归属/角色检查 → 短事务及必要行锁 → 数据写入和审计 → HTTP 响应。外部云接口、扫描、转码等耗时操作放到事务之外。

不要从客户端的 `owner_id`、`role`、`object_key` 推断权限。学生身份来自 `request.user`，教师范围来自后台保存的审核分配。UUID 只是标识符，不能替代权限检查。

## 新增一个模型字段

1. 在所属业务模块的 `models.py` 中增加字段，决定默认值、是否允许空值及必要约束。
2. 在 `services.py` 或表单中增加输入与状态校验，再补页面/接口输出。
3. 生成迁移并审阅迁移内容；不要改写已部署的旧迁移。
4. 在测试数据库运行迁移和相关检查，确认旧数据的兼容方式。

```powershell
.\.venv\Scripts\python.exe manage.py makemigrations submissions
.\.venv\Scripts\python.exe manage.py migrate
```

这些默认命令连接 `.env` 指定的 PostgreSQL。模型验证不代替数据库约束；普通 ORM `save()` 不会自动调用 `full_clean()`，服务函数必须明确校验。

## 新增一项业务功能

以“正式提交”为例，应继续在 `apps/submissions/services.py` 中实现已有的 `submit_for_review` 入口。需要校验活动时间、必交类别、数量、文件真实状态、文件归属、规则版本和草稿版本，锁定提交后生成不可变快照，再修改状态并记录审计。

如果需要排队，应在同一个事务内调用 `apps.jobs.services.enqueue()`。不要在事务提交前直接调用 `.delay()`；数据库回滚时不应留下一个仍能执行的业务任务。

每个功能至少明确：谁能调用、允许从什么状态开始、重复调用怎样处理、失败后如何恢复、返回什么错误。只读接口返回必要字段，列表采用有限数量；当前活动和草稿列表上限 100，正式列表可后续增加游标分页。

## 接入对象存储

在 `integrations/storage/` 增加适配器，实现 `base.py` 中的协议，使用厂商官方 SDK。然后在 `get_storage()` 中注册名称，再实现上传编排，最后开放页面。

上传编排需要补齐这些环节：

1. 调用额度预留服务，确认文件归属、大小、数量、活动时间和幂等键。
2. 在数据库事务之外初始化云端分片任务，记录云端任务 ID，失败时执行补偿。
3. 按需签发短期单片 URL，并限制片号、数量、任务状态和用户范围。
4. 续传时分页列出云端已传分片，以云端结果核对大小和进度。
5. 完成时核对所有片及总字节数，再合并、查询对象元数据、核验完整性。
6. 原子结算额度并创建 `FileAsset`，通过事务内 Outbox 登记检查任务。
7. 取消或过期任务先确认云端终止，再释放额度；补齐云端/数据库对账。

`reserve_upload()` 当前只提供本地预留示例；`expires_at` 尚未关联自动清理任务。它没有制造真实云文件，不能用于宣称已经完成上传。

系统硬上限同时存在于配置、校验函数和数据库约束中。将来如果提升到 10GB 以上，需要修改模型约束并新增迁移；只改 `.env` 不会绕过 10GB 上限。

## 增加文件检查规则

将检查器实现为 `ValidationRule`，输出 `Finding`，记录规则代码和版本。将文件解析与规则判断分开：解析器把文件变为有限大小的结构，规则判断该结构并定位错误。

上传元数据检查不能证明内容安全。未知类型、尚未扫描和无法解析的文件应保持待检查或人工处理状态。真正的文档/压缩包解析需要独立资源沙箱，限制磁盘、展开体积、内存、时间和网络；目前的 Celery 容器限制不等于已实现这种沙箱。

## 增加后台任务

`jobs/registry.py` 明确允许的任务类型和目标队列，队列消息只携带任务 UUID，完整状态保存在数据库中。发送是“至少一次”：发送成功后调度进程可能崩溃，因此处理器必须接受重复消息。

当前 `consume_event` 的事务适用于短数据库操作和探测任务。真实扫描、远程调用和批量打包应采用单独工作记录/租约：短事务领取任务 → 事务外执行 → 短事务核对租约并提交结果。不要直接在现有数据库锁内扫描大文件。

对外部副作用使用稳定对象键或业务幂等键，并区分可重试故障与永久失败。调整任务最大时间时，同时核对 Redis `visibility_timeout`、Outbox 重投时间和容器优雅退出时间。

## 新增页面或替换前端

当前页面集中在 `templates/`，共用 `base.html` 和 `static/css/app.css`。普通表单保留 `{% csrf_token %}`，JavaScript 请求发送相应 CSRF 请求头。无需额外的 Node 构建环境。

后续需要 Vue/React 时，可保留 `/api/v1/` 和业务服务层，把前端构建结果部署在同域。不要因为前端页面重写而复制权限和额度逻辑到浏览器中。

## 修改依赖

在独立虚拟环境中修改 `requirements/*.in`，安装后运行 `scripts/lock_dependencies.py` 更新精确版本快照，再检查兼容性。当前 `.txt` 是版本快照，未包含包哈希；容器基础镜像也未锁定摘要。

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements/dev.in
.\.venv\Scripts\python.exe scripts/lock_dependencies.py
.\.venv\Scripts\python.exe -m pip check
```

## 维护结构说明

`scripts/check_structure.py` 核对既定架构文件、Python 语法、应用注册和模块迁移入口，并生成逐文件说明。新增模块或文件时，同时更新该脚本的必要文件清单和用途描述。

```powershell
.\.venv\Scripts\python.exe scripts/check_structure.py --write-index
```

结构检查通过只能证明文件和静态结构完整；功能和并发行为仍需相应测试。
